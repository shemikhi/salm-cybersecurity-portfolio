AWS Cloud Security Lab

2023 — Present · 12 min read · Salm Bashemakh

Lab Overview

This lab focuses on AWS cloud security fundamentals — deploying infrastructure securely, monitoring for misconfigurations, and understanding attack paths specific to cloud environments.

Environment Setup

  • AWS Account: Free tier with CloudTrail enabled
  • Compute: EC2 instances across multiple VPCs
  • Identity: IAM users, roles, and policies
  • Monitoring: CloudTrail, CloudWatch Logs, GuardDuty

Security Configurations Tested

1. IAM Policy Misconfigurations

Created overly permissive IAM policies and tested privilege escalation paths using tools like Pacu and ScoutSuite.

# Check for overly permissive policies
aws iam get-policy-version --policy-arn arn:aws:iam::aws:policy/... --version-id v1

# Enumerate permissions with Pacu
run iam__enum_permissions

2. EC2 Security Group Auditing

Audited security groups for open ports (0.0.0.0/0), overly permissive ingress rules, and lack of egress filtering.

3. CloudTrail Log Analysis

Built queries to detect suspicious API calls including:

  • Unauthorized API calls (AccessDenied errors)
  • IAM policy changes outside business hours
  • Console login failures from unknown IPs
  • S3 bucket policy modifications

CloudTrail Detection Queries

fields @timestamp, eventName, eventSource, userIdentity.arn, sourceIPAddress
| filter errorCode = "AccessDenied"
| stats count(*) by eventName, sourceIPAddress
| sort count(*) desc

Key Takeaways

  • CloudTrail is essential but not sufficient — enable GuardDuty for anomaly detection
  • IAM policy conditions (IP restrictions, MFA requirements) significantly reduce blast radius
  • S3 bucket policies are frequently misconfigured — audit them regularly
