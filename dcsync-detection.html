Active Directory Attack & Detection Lab

2022 — Present · 15 min read · Salm Bashemakh

Lab Overview

This home lab was built to simulate real-world Active Directory attack chains and develop detection capabilities around them. The environment consists of a Windows Server 2019 Domain Controller, two Windows 10 client VMs, and a Kali Linux attack machine — all running on VMware Workstation.

Environment Setup

  • Domain Controller: Windows Server 2019 (DC01.corp.local)
  • Client 1: Windows 10 Enterprise (WKSTN01)
  • Client 2: Windows 10 Enterprise (WKSTN02)
  • Attacker: Kali Linux 2024.2
  • SIEM: Splunk Enterprise (free license)
  • Telemetry: Sysmon + Windows Event Forwarding

Attack Chains Simulated

1. Kerberoasting (T1558.003)

Used Rubeus to request service tickets for SPN-registered accounts. Captured TGS-REP hashes and attempted offline cracking with Hashcat.

# Request all service tickets
Rubeus.exe kerberoast /outfile:hashes.txt

# Crack offline
hashcat -m 13100 hashes.txt wordlist.txt

2. AS-REP Roasting (T1558.004)

Identified accounts with "Do not require Kerberos preauthentication" flag set. Used GetNPUsers.py from Impacket to capture AS-REP responses.

3. DCSync (T1003.006)

Simulated a compromised account with DCSync rights (Replicating Directory Changes) to pull password hashes from the NTDS.dit database.

4. ACL Abuse & Lateral Movement

Used BloodHound to map attack paths through misconfigured ACLs. Performed lateral movement via PSExec and WMIexec after credential compromise.

Detection Engineering

For each attack, I built Splunk detection queries correlating multiple data sources:

Kerberoasting Detection SPL

index=wineventlog EventCode=4769
| stats count by Account_Name, Service_Name, Client_Address
| where count > 5
| eval risk_score=case(count>20, "High", count>10, "Medium", 1=1, "Low")
| table _time, Account_Name, Service_Name, Client_Address, risk_score

DCSync Detection SPL

index=wineventlog EventCode=4662 OR EventCode=5136
| search Properties="Replicating Directory Changes"
| stats count by Account_Name, Object_Name, Properties
| where count > 3

Key Takeaways

  • Single-event detection is noisy — correlation rules reduce false positives by 70%+
  • Sysmon Event ID 10 (ProcessAccess) is critical for detecting credential dumping tools
  • MITRE ATT&CK mapping helps prioritize which techniques to detect first based on your threat model
"The best defense is understanding the offense. Every detection rule I write starts with me successfully executing the attack first."
