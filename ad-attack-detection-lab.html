Using MITRE ATT&CK for Blue Team Defense

2025-07-05 · 8 min read · Salm Bashemakh

Why MITRE ATT&CK?

MITRE ATT&CK isn't just a framework — it's a common language for defenders. When I map my detections to ATT&CK, I can communicate coverage gaps, prioritize engineering efforts, and speak the same language as red teamers.

Building a Coverage Matrix

Start with your current detections. For each alert, identify the technique it maps to. Then visualize coverage:

Example Coverage Table

Technique          | Detection | Data Source       | Confidence
-------------------|-----------|-------------------|----------
T1078 Valid Acc    | ✓         | Windows Event 4624| High
T1558.003 Kerberoast| ✓        | Event 4769      | Medium
T1003.006 DCSync   | ✓         | Event 4662        | High
T1059.001 PowerShell| ✓        | Sysmon EID 1      | Medium
T1021.002 SMBExec  | ✗         | —                 | None

Identifying Gaps

Focus on techniques that are:

  • High-frequency in your threat model
  • Easy for attackers to execute
  • Currently unmonitored in your environment

Practical Implementation

I maintain a simple JSON file mapping each detection rule to ATT&CK techniques. This feeds into a dashboard showing coverage by tactic:

{
  "rule_name": "Detect_Kerberoasting",
  "technique": "T1558.003",
  "tactic": "Credential Access",
  "data_source": "Windows Security 4769",
  "confidence": "Medium",
  "last_tested": "2025-07-10"
}

Key Takeaways

  • Don't try to detect everything — prioritize based on your threat model
  • Test your detections regularly with attack simulation
  • Share your coverage matrix with stakeholders to justify engineering time
